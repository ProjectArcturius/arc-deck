# Arc Deck · 工作流

这份文档只回答一个问题：**现在这条线上有哪几件事、各做到哪了。**
产品与设计规格不在这里（那是 `AGENTS.md` 与 `docs/ARCHITECTURE.md`）。

## 两 branch 的分工**已作废**

原先是按「本机一条 + Linux 一条」切的：本机做功能，Linux 做**独立事实核查**
（第二平台跑 `arc-deck-dsh`、Windows 耦合清单、第二份日志语料）。

**作废原因：Linux 端无法工作。** 所以那不是「暂时 suspend」，是这条路不成立 ——
写在这里是为了**下次不要再提**同一个方案。下面记清楚原本指望它证明什么、
现在还剩什么，比删掉这份文档有用。

| 原 B 的事 | 现在 |
|---|---|
| 在第二个平台上跑 `arc-deck-dsh` | ❌ **做不了**。所以「它只在 Windows 上跑过」这个前提**至今没有被验证** |
| 第二份会话日志语料上跑重放不变式 | ❌ **做不了**。P9 想找的那份「权威全文缺席」的日志仍然没有 |
| headless 宿主原型（P1 方向的平台无关部分） | ❌ 同上，且归属本来就没定 |
| **Windows 耦合清单** | ⚠️ **能在本机做，但性质变了**：只能读代码出「候选清单」，**验不了**哪一处真的会坏。标注必须写清「未验证」 |

**这一条是这次合并最要紧的代价**：P1 的方向是「全信任桌面外壳引 `arc-deck-dsh`」，
而那个方向的**唯一未验前提**就是「这一层不绑 Windows」。现在它仍然未验，
只是从「等着验」变成了「谁也验不了」。将来真要在别的平台用这一层，
**第一件事就是拿一台机器把它跑起来** —— 不要相信清单。

### 为什么 A5 最大却排在最后

A1–A4/A6 让**协议层**的话能说圆（能开、能对、能翻页、能分流），
但它们都不产出界面。真正卡住产品的是 P1：UWP 是 AppContainer，起不了内核、
读不到包外路径、连不上回环 —— 界面再好也拿不到数据。
所以外壳那件事是绕不过去的，只是它比前面几件大一个量级，
动手前该先把它的形状定下来（走哪个宿主、和 `kanesumi/` 什么关系），
那是**设计决定**而不是编码活。

## 已知的坑（都记在 `AGENTS.md`，这里只列名字）

- 那个 latent bug 仍留着：`HarnessMux` 读了 `streamId` 却没用它分流（A4）
