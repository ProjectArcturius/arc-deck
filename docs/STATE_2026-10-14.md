## 三、在 Linux 机上接手

**未验证**：本轮没能在 Linux 上编译或运行（`ssh ether` 不通；rustup 镜像拿 Linux std 返回 403）。`cfg(unix)` 的进程组、分离运行与 `kill -KILL -- -<pgid>` 只做了人工核对。下面是预期步骤，第一次跑请把结果补进 PRODUCT_PLAN §10.2b。

```bash
# 前提：rustup 的 stable（edition 2024 需要 ≥ 1.85；Windows 上用的是 1.95）、node + npm、git
cargo build --release -p arc-deck-cli        # 只编产品 crate：kanesumi/ime-probe 是 Win32 FFI，全 workspace 在 Linux 上大概率编不过（未验证）
install -m755 target/release/arcdeck ~/.cargo/bin/
arcdeck runtime install                      # 钉住的 DSH 装进 ~/.local/share/arcdeck/runtime/
arcdeck config init                          # ~/.config/arcdeck/arcdeck.json
arcdeck auth set opencode-go                 # 粘贴密钥，Ctrl+D
cargo test -p arc-deck-core -p arc-deck-dsh -p arc-deck-cli --features arc-deck-cli/test-runtime   # 离线，不调模型

# 冒烟（会用一点模型额度）：在一个临时 git 仓里
arcdeck run task.md --accept "git log --oneline -1" --detach && arcdeck wait <id> --timeout 10m && arcdeck report <id>
```

Linux 上要特别看的三件事：分离运行在 ssh 断开后是否存活；`arcdeck cancel` 后进程组是否真的全退了；
`danger-full-access` 下 worktree 里提交是否正常（Windows 上 `workspace-write` 会拒，见 §10.2b）。
