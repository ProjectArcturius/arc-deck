# Arc Deck 1.0.0（草稿）

发布范围是 `arcdeck` 的 Windows x64 TUI 与 headless；桌面 GUI 不在本版内。
Linux 的 AUR/deb recipe 和构建交接已准备，本轮按用户指示略过 Linux 二进制构建与资产上传。

## 修复

- 续轮挂起：持久请求编号不再随 SessionClient 重建而归零，避免重连/切授权后被 DSH 当旧请求去重。
  编号加入时间与进程内全局序号，也区分 PID 复用。已结束的 follow 在下一次发送前重新订阅；
  取消后的旧流不能复活轮次或留下幽灵正文。
- 扫描条旁的闪烁光标：绘制前隐藏硬件光标，以同步刷新提交画面与输入框光标位置。
- `ENOSPC` / 磁盘写满独立分类为 `HOST_DISK_FULL`，不再建议当作模型/网络错误重派。
- Windows DSH `0.2.1-alpha.2` 的 SDK shutdown 会偶发 libuv 关闭断言 `0xc0000409`：
  该版本改由已收齐结果后的进程树收尾，绕过坏掉的上游清理路径；不修改或 vendor DSH。
  如果运行时已经自行异常退出，会记录 `runtime_exit_code` 和 `RUNTIME_SHUTDOWN_FAILED`，保留答案但不报 completed。
- CLI 的夹具测试明确要求 `test-runtime`，默认构建/all-targets 不再误引用没有编译的假 provider。

## 验证

- 四个产品 crate 的离线套件 **525 项通过**：core 85 + 契约 7，dsh 112，TUI 227，CLI 50 + 端到端 44。
- 真 DSH + 本地假模型（零配额）：工具执行中取消 → 立即续聊 → 重启内核 → 恢复同一会话续聊。
- 真 DSH 的 17 条工具/权限联通测试全部通过，含只读拒绝、工作区边界、shell/子 agent 限制与真实提交。
  收尾修复前这轮曾有 2 条因真实 `0xc0000409` 失败；保留失败事实，修后 17/17。
- Windows release 真终端：42→43 上下文、流式输出后 Esc、下一轮 RECOVERED、历史恢复、搜索/子会话弹层、
  退出与无残留内核；扫描条期间 500 次采样，硬件光标始终在输入区或隐藏。
  探针的「恢复后已取消」断言最初只认 `已取消`，conhost 实际显示 `· 取消`，已按既有兼容判据修正。
- ZIP 脚本安装 → 版本检查 → 用户 PATH → 卸载 → PATH 原值逐字恢复通过。
  Inno Setup 安装器编译/解压通过；本环境拒绝 Setup 子进程写用户 TEMP、开始菜单和卸载注册表，
  **完整向导安装/卸载尚未验证**。安装器失败回滚已确认移除测试文件。
- Clippy 完成，已有 core/dsh/cli 告警仍在；严格 `-D warnings`、全仓 fmt 检查不通过，
  原因是既有代码格式/告警，未做全仓无关重排。TUI 无新告警。

## 下载与安装

- `arcdeck-1.0.0-windows-x86_64.zip`：解压后双击 `install.cmd`；也可直接运行 `arcdeck.exe`。
- `arcdeck-1.0.0-windows-x86_64-setup.exe`：用户级向导安装，待普通桌面环境完成安装验收。
- `arc-deck-1.0.0-source.tar.gz`：本轮完整源码，供 Linux 编译；不含本机密钥、配置、会话或 REFS。
- `arc-deck-1.0.0-aur.tar.gz`：带源包 SHA256 的 PKGBUILD；未向 AUR 服务器提交。
- 对照 `SHA256SUMS-windows.txt` 与 `SHA256SUMS-source.txt` 验证资产。

先安装 Node.js >=24（含 npm）与 Git，之后 `arcdeck config init` → `arcdeck runtime install`
→ `arcdeck auth set <provider>`。DSH 仍单独安装，默认关闭会话日志上传。

安装详见 [INSTALL.md](../INSTALL.md)，Arch 上构建 AUR/deb 与补传资产详见 [LINUX_RELEASE.md](../LINUX_RELEASE.md)。

## 发布前的边界

草稿不等于已公开发布。确认修复源码已提交并推送，v1.0.0 的 target 指向该版本，再正式发布；
未取得提交/推送授权时，工作区源码通过 source 资产交付，BUILD-INFO 会如实标记 dirty。
Linux 尚无本轮运行证据，不能把 recipe 或 bash 语法检查当作 Linux 构建/安装通过。
Arch 真终端与 OpenCode 同终端的最终视觉对照仍留给用户；macOS、GUI 接线、M2d 对照门不在本版完成声明内。
