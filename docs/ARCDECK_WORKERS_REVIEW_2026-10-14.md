# 用 arcdeck 工人替代 OpenCode 工人：本轮实测、优势与对 Ether 的意义

日期：2026-10-14。依据：本仓 M4 派工全过程（`docs/M4_PLAN.md`、`tasks/m4/`、各提交正文）与 arcdeck 状态目录里的
真实计数；对照对象是 Ether 现行的 OpenCode 工人链（`Ether/tools/dispatch/oc.sh` + `runner.sh`、`docs/DISPATCHER.md` §三）。

**先说边界**：本轮是「用 arcdeck 派真活」的第一次规模化使用，不是对照实验。同一批任务没有交给 OpenCode 工人再做一遍，
所以「质量更好 / 成本更低」**没有被 A/B 证明**（那是 PRODUCT_PLAN 的 M2d）。下文把**量到的**、**机制上成立的**与
**还没证明的**分开写。

## 一、一句话

调度的单位从「一个在后台跑、要看日志猜状态的进程」变成「一件有状态、有验收、有事实报告的任务」。
本轮 12 次运行、约 4.2 小时工人时、1945 次工具调用里，**没有一次工具调用漏成文本、没有一次模型重试**；
三个工人因磁盘写满同时死亡，**进度一行没丢**，同 id 续做后全部完成。

**成本**：与 Ether 上**同模型、同网关**的 OpenCode 工人比（§三），缓存命中率**不是**差别（98.2 % vs 99.2 %）；
差别在**每一步现付的未命中输入少了约一半（−50 %）**，按同一张价目表每步便宜约 13 %。任务不同，这是参考值不是 A/B。
**可靠性**：Ether 历史上最贵的几次事故 —— 429 被误判成余额耗尽烧光余额、读到旧文档里的错误串被当成当前错误、
DSML 续跑 8 次全失败、ECONNRESET 打断一小时零提交 —— 都出在「靠 grep 日志猜状态」这一层，arcdeck 把这一层换成了结构化状态与失败码。

## 三、Ether 历史施工记录对照（2026-10-15 补）

数据来源：本机（Windows）OpenCode 的 `opencode.db`（**只读快照**，只读 session / message / part 三张表，没碰凭据表）
中工作目录在 `.oc/wt/` 下的 60 个工人会话；Ether `docs/STATE_2026-10-0*.md` 与 `STATE_2026-10-1*.md` 里调度者记下的工人事故。
**Arch 那台机器连不上**（`ssh ether` 超时），那边的会话不在样本里 —— Ether 的工人大多跑在 Arch，所以样本偏小。

### 3.1 同模型同网关的用量（OpenCode `opencode-go/deepseek-v4.1-flash` · variant high）

价目表从 OpenCode 自己记的每条消息费用**反推**，3004 条带价消息残差为 0：未命中输入 $0.15 / M、缓存命中 $0.003 / M、
输出（含推理）$0.60 / M。arcdeck 侧用同一张表折算（arcdeck 报的输出 token 含推理）。

| | OpenCode 工人（Ether，24 会话） | arcdeck 工人（本仓本轮） | 差 |
|---|---|---|---|
| 步数（模型调用） | 1608 | 1691 | |
| 工具调用 | 1857 | 1945 | |
| 缓存命中率 | 98.2 % | 99.3 % | 几乎一样 —— **不是 DSH 的优势** |
| 每步未命中输入 | 2398 | 1204 | **−50 %** |
| 每步缓存读取 | 132.7 k | 167.9 k | +27 %（便宜的那部分） |
| 每步输出（含推理） | 813 | 657 | −19 % |
| 每步费用 | $0.00124 | $0.00108 | **−13 %** |
| 总费用 | $2.00 | ≈ $1.82 | |

读法：DSH 把更多上下文放进缓存（每步缓存读取多 27 %），换来现付的未命中输入少了一半；输出也略少。
**限制**：两边的任务不同（Ether 是合成器 / Rust 渲染，本轮是 TUI 与授权），每步的上下文大小天然不同；样本里 OpenCode 一侧
有 6 个会话是 0 token 的失败启动。所以这是**方向一致的参考**，不是对照实验 —— 要结论仍需 §八 的同任务并排。

| 10-11 | 长提示词撞 Windows 参数长度上限，exit 126 | 改短提示词重派 | 任务书走文件；`--prompt -` 从 stdin 读原文（本仓 5c402b9 有 6 万字符的回归测试） |

### 3.3 结论

- **「更便宜」**：在同模型、同网关、同价目下，**每步约便宜 13 %**，来源是现付输入少了约一半 —— 方向成立、幅度待同任务对照确认。
  「缓存命中率更高」不是理由，两边都在 98–99 %。
- **「更强」**：没有可比的质量数据。本轮 5 件合入、0 件退回；Ether 历史上也有一次过与复验退回（如 w-scroll-tracker），
  任务难度不同，不能比。
- **最确定的收益在可靠性与调度成本**：Ether 历史上最贵的事故都出在「靠 grep 日志猜状态」这一层，而这一层正是 arcdeck 换掉的部分。

## 四、和 Ether 现行 OpenCode 工人链逐项对照

| 维度 | 现行：`oc.sh` + `runner.sh`（OpenCode） | arcdeck 工人 | 本轮证据 |
|---|---|---|---|
| 看状态 | `ssh … pgrep`、tail 日志、`status_panel.ps1` | `arcdeck status <id>` 一行 + 退出码（完成 / 在跑 / 卡死 / 出错各有码）；健康由**读者按时间戳**算 | 全程只读这一行；当前在跑哪个工具、跑了多久直接写在行里（`tool:pwsh 4m25s "cargo test…"`） |
| 进程死了 | 日志不再增长，靠人发现 | 监工停跳 → 读者判 `dead`；**死进程不能自称健康** | 磁盘写满时三件同时死，`status` 一分钟内显示 `dead` |
| 卡死 | 输出 30 分钟不增长就杀（`STALL_SECS`） | 等模型与跑工具**分开计时**（600 s / 1800 s），有界续跑 | 本轮没有出现卡死（所以续跑路径本轮没被真实触发） |
| 失败原因 | grep 日志里的错误字符串决定续不续、换不换模型 | 结构化失败码 + `retryable`；报告直接回答「再派一次能解决吗」 | `blocked` 的两件报告都写着「不能 —— 先看事实」，指向的确实是验收这一项 |
| 工具调用漏成文本（DSML） | 检测末尾 DSML 文本后自动续跑，最多 8 次 | 计数器 `tool_call_as_text`，单列报告 | 1945 次工具调用里 **0** 次（检测只看每轮正文尾部；见 §六） |
| 验收 | 人审；runner 只看有没有「范围外」 | `--accept` 命令进任务书；**命令结果是事实**，进报告；没验收的 `completed` 不算通过 | 抓出 2 件「工人说跑过、实际没按原样跑」—— 一件是加了 `--quiet`，一件是磁盘满时没跑完 |
| 事实与陈述 | 只有模型的最终发言 | 报告分两栏：**Arc Deck 采集的事实**（验收、改动文件、用量、未验证项）与**模型的陈述（不是证据）** | 每件都先看事实栏；改动文件清单与派工者 `git status` 逐一吻合 |
| 后台化 | 必须 `nohup`，只加 `&` 任务会被一起杀掉（2026-10-02 实测） | `--detach` 握手：**工人接住（写出状态）才返回**，接不住报原因 | 修掉两个 Windows 问题：常驻 / 闪烁的终端窗口、`$(arcdeck run --detach)` 挂到任务结束（b227176，对照实验 22.9 s → 1.6 s） |
| worktree 与续做 | runner 里的 shell 片段 | `--worktree` 建分支与目录；**同 id + `--rerun`** 复用原 worktree，未提交的进度原样在 | 三件死掉的任务各写一页续做任务书，全部接着做完 |
| 权限 | OpenCode 的 permission 配置；Ether 工人实际是全权 | 授权级别（readonly / workspace / full）**落到 DSH 执行层**：只读与 Plan 由 OS 沙箱强制、关 shell 即摘工具；表达不了的组合**拒绝启动**；提交 / 推送做不到的如实列为「未验证」 | M3 合入（f545990）后真实冒烟一次通过，报告里出现两条「未验证」 |
| 用量与成本 | 供应商后台 / 手算墨点公式 | `arcdeck usage`：每件的未命中 / 命中 / 输出，只报 provider 给的数，不编费用 | 本页的表就是它出的 |
| 派工关系 | 无 | `--by` 记进状态（`assigned_by`），供监控程序画任务流向 | 本轮全部 `--by claude` |

## 五、新的调度体验（派工者视角）

1. **一个循环就够**：派出 → 每次只读 `status` 一行 → 终态读 `report` → 复跑验收 → 读 diff → 合入。
   不需要打开日志；只有在报告的事实栏说不通时才去看 `events.jsonl`（本轮只看过两次：磁盘写满、验收没按原样跑）。
2. **「完成」有含义**：带了 `--accept` 的 `completed` 意味着验收命令真的跑过并通过。反过来，arcdeck 宁可判 `blocked`
   也不放过一条没按原样跑的验收 —— 本轮两次「假 blocked」的代价是派工者各复跑一遍（约 1 分钟），换来的是不会有「假完成」。
3. **出事不丢活**：C 盘写满、三个工人同时死，处理是：清出空间 → 每件写一页续做任务书 → 同 id `--rerun`。
   改动都在 worktree 里，续做的工人先读已有进度再接着做。
4. **可以并行**：本轮同时 5 件（16 核 / 32 GB 够用）；瓶颈是磁盘（每件构建目录 0.4–1 GB），已改到 D 盘。
5. **换调度者成本低**：队列、依赖、派工命令模板、收工七步与踩过的坑都在 `tasks/m4/README.md`；
   状态都在文件里，`arcdeck status --all` 一眼看全 —— 替班（sol）接手不需要这段对话。

## 六、还没证明的（不要把它们当成结论）

- **质量与成本没有 A/B**：同一批任务没有交给 OpenCode 工人做过。§三 的用量对照用的是不同任务，只能说明方向。
  （初稿曾暗示 99.2 % 的缓存命中率是优势；查了 Ether 的历史数据后更正：同网关的 OpenCode 工人也有 98.2 %。）
- **DeepSeek 的专属优势本轮没用上**：路由是 opencode-go 网关经 DSH pi-ai，不是 `deepseek-official`。DSH_FINDINGS 的结论是
  DS 协议与缓存的优势只在官方路由上成立；本轮每步现付输入少一半，来自 DSH 的 loop 工程（上下文更多地落在缓存里），不是 DeepSeek 官方协议。
- **DSML 0 次**的口径：arcdeck 只检查每轮助手正文的尾部；Ether 那边的 DSML 问题主要出在 intern-ai 端点。两边不是同一个端点，
  不能直接说「arcdeck 解决了 DSML」。
- **卡死续跑**没有被真实触发过（本轮没有卡死）；Windows 上的监工判死只靠心跳（Linux 有 pid + 启动时刻的即时判死）。
- **执行层拒绝越权已有实测**（w4-m3b-negative，fb4d482）：脚本化假模型端点驱动真实 DSH，17 条负例 + 正例对照全过 ——
  只读写入、关 shell 后调命令、越界写、提权、子 Agent 里再写、关网络，全部拦住。**但有三处实测确认的缺口**：
  `commit=false` 挡不住 `git commit`；只读档能读 workspace 之外的文件；workspace-write 的写根含系统临时区。
  `workflow` / PTC 未测。还有一个工人终报的说法不实（说验收「逐字原样跑过」，实际接了管道）—— 报告的事实栏没被它骗过。
- **一处已知的误报**：磁盘写满被归类成 `MODEL_FAILURE`（应为环境问题，不可重试直到腾出空间），已记入 `docs/M4_PLAN.md` 待修。

## 七、对 Ether 开发的益处

1. **runner 的启发式变成结构化状态**：`runner.sh` 121 行里的大半 —— 输出增长看门狗、grep 错误串决定续跑与换模型、
   DSML 尾部检测、额度兜底 —— 在 arcdeck 里是监工、失败码与有界续跑。Ether 侧剩下的只是「派哪件、给哪台机器」。
2. **替班更容易**：DISPATCHER 的开工流程第 3 步（ssh pgrep、ls worktree、看日志是否在增长）可以收成
   `arcdeck status --all`。用户在 Ether AGENTS 里明确讨厌被反复要求跑命令抓日志 —— 一行状态正好对上。
3. **MANUAL_QUEUE 的合并门槛可以写成 `--accept`**：门槛命令进任务书，「完成」就等于门槛跑过；审查只需复跑与读 diff。
4. **研究 / 探索类任务可以真的只读**：Plan / readonly 现在由沙箱强制、关 shell 即摘工具。Ether 里「去源码里查清楚 X」
   这类任务可以放心派给只读工人，不必担心它顺手改了东西。
5. **两台机器同一个二进制**：Windows 与 Arch 都实测过（Arch 含真实 DSH 派工、取消、杀监工判死、孤儿回收、worktree 真提交）。
6. **用量看得见**：每件任务的命中 / 未命中 / 输出直接可读，对照 Ether 的额度规则（「前缀稳定就是省钱」）有了逐件数据。
7. **监控接得上**：`--by` 记下派工关系，`cute-agents-monitor` 能画出「谁派给谁」。
